# Карта возражений и оценка обработки по LAER

## Категории возражений (фиксированный набор)

`price`, `timing` (сроки), `need/fit` (потребность/соответствие),
`trust/risk` (доверие/риск), `authority/process` (полномочия/процесс),
`competitor`, `implementation` (реализация).

Для каждого возражения обязательны: точная цитата клиента, тайм-код, стадия
звонка, `severity` (low/medium/high), `confidence` (0–1) и статус обработки:
`resolved`, `partially_resolved`, `deferred`, `unresolved`, `not_observable`.

## LAER — пять проверяемых шагов менеджера

| Шаг | Что подтверждает цитата менеджера |
|---|---|
| **Listen** | выслушал без перебивания (реплика клиента завершена до ответа) |
| **Acknowledge** | признал значимость concern'а («понимаю, почему это важно…») |
| **Explore** | задал вопрос о причине/контексте возражения |
| **Respond** | ответил релевантными доказательствами или вариантами именно на это возражение |
| **Confirm** | проверил снятие вопроса («ответил на ваш вопрос?») |

## Обязательные требования

1. Шаг LAER засчитывается только по наблюдаемой реплике менеджера с
   тайм-кодом; общий питч НЕ считается ответом на возражение.
2. Не выдумывать цитаты; при недостатке данных — `not_observable`.
3. Скрытые возражения (вопросы-сомнения, паузы после цены) фиксировать с
   пониженным `confidence`, не выдавая их за явные.
4. Формат совпадает с контрактом `objections[]` в `prompt.md` и
   `backend.py:normalize()` — не менять имена полей.

открытые наборы skills: louisblythe/Sales-Skills (MIT) — идеи objection
handling / discovery, переписаны своими словами без копирования текста.
